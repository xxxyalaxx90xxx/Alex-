# Kubernetes Cluster Analysis Script - Example Output

This document shows an example of the output generated by the `analyze_k8s.sh` script.

## Usage

```bash
# Basic usage
./analyze_k8s.sh

# Custom output file
OUTPUT_FILE=my_report.txt ./analyze_k8s.sh

# Custom kubeconfig location
KUBECONFIG_FILE=/path/to/kubeconfig ./analyze_k8s.sh
```

## Example Report Sections

### 1. Cluster Information
- Kubernetes version
- Cluster info (API server endpoint)

### 2. Node Analysis
- Node status (Ready/NotReady)
- Node resource allocation (CPU, memory)
- Hugepages configuration (if configured)

### 3. Pod Analysis
- All pods across namespaces
- Pod count by namespace
- Pod status summary (Running, Pending, Failed, etc.)
- Pods not in Running state (for quick issue identification)
- Pod resource usage (top 10 by memory)

### 4. Namespace Analysis
- List of all namespaces in the cluster

### 5. Service Analysis
- All services across namespaces

### 6. Network Analysis
- CNI plugin status (Flannel)
- Network policies

### 7. Storage Analysis
- Persistent volumes (PV)
- Persistent volume claims (PVC)
- Storage classes

### 8. Events Analysis
- Recent events (last 20)
- Warning events

### 9. Component Health
- Component status (scheduler, controller-manager, etcd)
- API server health

### 10. Configuration Analysis
- ConfigMaps in system namespaces
- Secret counts by namespace

### 11. Analysis Summary
- Total nodes and ready nodes
- Total pods and running pods
- Total namespaces
- Overall cluster health assessment (HEALTHY/WARNING/UNKNOWN)

## Health Assessment Criteria

The script provides an overall health assessment:

- **HEALTHY ✓**: All nodes are ready and all pods are running
- **WARNING ⚠**: Some nodes are not ready OR some pods are not running
- **UNKNOWN**: Unable to determine health status

## Prerequisites

- `kubectl` must be installed and available in PATH
- A valid kubeconfig file must exist (default: `$HOME/.kube/config`)
- The user must have appropriate permissions to query cluster resources

## Troubleshooting

If the script reports warnings:
1. Check the "Pods Not in Running State" section
2. Review "Warning Events" for error messages
3. Examine "Node Status" for node issues
4. Check "Component Health" for system component problems

## Integration with CI/CD

The script can be integrated into CI/CD pipelines for automated cluster health checks:

```bash
# Run analysis and check exit code
./analyze_k8s.sh

# Parse report for specific issues
grep "WARNING" k8s_analysis_report.txt && exit 1 || exit 0
```
